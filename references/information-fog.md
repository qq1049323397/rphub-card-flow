# 信息迷雾（防剧透）

> **前置条件 —— 先读这一行。**
> **主线是作者提出的，不是本 skill 的默认项。**
> 作者给的 docs、原稿、或者聊天里说了「我要一条按顺序推进的剧情线」→ 才走这一节。
> 作者没提 → **不做阶段机、不写排期条目、不设迷雾层**。
> 纯肉卡、单场景卡、日常陪聊卡看完这一行就可以关掉本页。
> **AI 不许自己给卡加主线。**

---

## 1. 这条规矩只有一句话

**条目正文只写「此刻能观察到什么」，不写「以后会发生什么」。**

判据：把这条正文读给一个刚进场的角色听 —— 他觉得这是在描述现在，还是在预告未来？

「以后」由**排期条目**负责。排期条目是唯一允许写未来的地方，因为它存在的意义就是排期。
其他所有条目（人物、场所、道具、事件、传闻、能力、组织、规则、索引）一律只写现在。

---

## 2. 为什么世界书会自然而然地写出未来

三个来源，每个都实测撞过：

| 来源 | 长什么样 |
|---|---|
| 作者素材本身是全剧视角 | 人设文档直接写着结局、写着第几集会怎样 |
| 搭阶段机时的惯性 | 每条阶段条目天然要交代「这一集发生什么」，写着写着就把后几集也交代了 |
| 角色随主线演化 | 人物条目会想加「第 N 集时的她」，于是把每个时期的她都写进去 |

第三条最隐蔽。它看起来是在「把角色写厚」，实际是把整条时间线塞进了一条人物条目。

---

## 3. 六类条目各写什么

| 条目 | 写 | 不写 |
|---|---|---|
| **人物** | 性格、外貌、语气、习惯、关系、**方向**（她会往哪动、什么会推动她） | 具体某一集的她、未来的数值、未来的身体状况 |
| **场所** | 感官、外观、空间、会在这里遇到谁、在这里能做什么 | 这里将来会发生什么、以后会变成什么样 |
| **道具** | 它是什么、现在在谁手里、怎么用 | 它将来会到谁手里、以后会变成什么 |
| **事件** | **现在到哪一步了**、已经发生了什么 | 精确的未来起止日期、还没发生的后续 |
| **传闻** | 镇上人怎么传（**走样的版本**） | 真相。真相归排期条目 |
| **能力 / 组织** | 它是什么、怎么运作、边界在哪 | 它以后会被谁拿到、会怎么升级 |
| **排期条目** | 这一集发生什么 ← **只有这里能写未来** | — |

**人物条目给方向，排期条目给进度。**
这是两条不同的信息，不要混进同一个家。人物条目写「什么会推动她往哪动」，
排期条目写「现在走到第几集了」。前者永远有效，后者随时间作废。

---

## 4. 字段名和内容时态必须一致

正文里出现 `当前状态` `现状` `目前` `此刻` `现在在谁手里` `如今` 这类字段名时，
后面跟的必须是**开局那一刻**的值。

实测反例（一张 186 条的剧情卡，58 条都长这样）：

```
人物·鹿岛夏希
当前状态：核心五十二点三度，组织碳化率百分之十四，右眼视力永久退化……
```

**这条正文里一个剧透词都没有。** 没有「第几集」、没有未来日期、没有结局字样。
但整段写的是结局。闸门的任何关键词检查都抓不到它。

修法：把「当前状态」拆成两个家 ——
人物条目里写**她的体质是怎么回事**（恒定成立的事实），
排期条目里写**她现在烧到多少度**（随集数变的值）。

---

## 5. 一个事实只能有一个家

同一件具体事实在几个条目里各写一遍，会有两个后果：
改一处等于没改（另外几处还在）；几处会互相漂移（一个说十四，一个说十六）。

实测过的例子：一个角色的眼睛情况同时出现在人物条目、能力条目、事件条目里，
三处的说法不一样，模型每轮挑一个用。

**同一个事实出现在两个地方，就是两个真相。**

---

## 6. 传闻要走样

传闻条目记的是「镇上人怎么传」，不是「真相是什么」。

角色复述传闻时，照走样的版本复述。**不许替他补对。**
真相住在排期条目里，等剧情走到那一步再放出来。

---

## 7. 独白同罪

玩家视角的独白受同一套限制。玩家不知道的事，独白里也不出现。

禁句式：`他还不知道的是……` `她不知道，此刻……` `殊不知……`
这类句子等于从全知视角往玩家脑子里塞信息。

---

## 8. 怎么定这张卡的迷雾（动笔前）

**这一步是 AI 的阅读理解任务加作者确认，不写脚本。**
和「定裸名」（SKILL.md 第 0.5 步）同构 —— 中文的剧情边界抽不准，
写成正则只会给出边界错误的假答案。

读这张卡自己的素材，写下四件事，**给作者确认后才动笔**：

1. **这张卡的阶段轴叫什么？** 集 / 幕 / 章 / 话 / 阶段 / 剧情节点 / 日期。
   从卡和素材里读，不要预设。
2. **每个阶段，谁已经知道了什么？** 分三档：亲历 / 听说（允许走样）/ 不知道（默认档）。
   **没有明确写过的，按「不知道」算。**
3. **哪些条目属于排期条目？** 这些是唯一允许写未来的。
4. **哪些条目的哪个字段写了未来？** 列出来，这些就是要改的。

第 4 条是实际动工的那一条。实测：一张 186 条的剧情卡，
有 58 条（31%）的「当前/现状」字段装的是结局状态。

### 为什么不能靠一条总规则

实测过：把一条「信息迷雾」元规则塞进 system prompt（`constant: true`，`system_top`），
拿未修复的卡跑对照实验 —— **没压住**。

| 变体 | 终局词命中 |
|---|---|
| 原卡 | 0 |
| 去掉阶段表剧名 | 0 |
| + 迷雾元规则 | 0 |
| 去剧透 + 迷雾 | 3 |
| 去剧透 + 酒馆版迷雾 | 3 |

条目正文里就写着结局，模型看到了就会说。**一条总规则管不住正文里的具体事实。**
真正治住它的是**改正文**：把 58 条里的未来值换成开局值。

这条正好印证「世界书就是世界书」——
**迷雾不是 prompt 层的一个开关，是条目正文本身的写法。**

---

## 9. 常驻条目最危险

`constant: true` 的条目每轮都在 prompt 里，模型把它当成永远成立的事实。
排期信息漏进常驻，等于每轮都提醒一遍「后面会怎样」。

常驻层该放的是**永远成立的规则、契约、索引**，不放任何随时间变的东西。

---

## 10. 闸门能查什么、不能查什么

**能查（不需要读懂剧情）：**

| 观察项 | 报什么 |
|---|---|
| 字段时态 | 字段名说「当前/现状/现在」，值里却是会漂的数（数字、度数、百分比、日期） |
| 事实重复 | 同一句具体事实在多个条目里逐字重复 |
| 常驻里的排期标记 | 常驻条目正文出现 `第N集/幕/章/话/节/阶段` 这类编号、具体日期、结局类词 |
| 正文里的排期标记 | 普通条目正文出现同样的标记 |

**不能查：**

一张卡里有没有「作者排好的剧情线」，脚本判不出来。
`阶段·C1_神物`（玩家驱动的状态档，rouka 的做法）和
`主线·第1集·电费单`（作者排期，剧情卡的做法）
在脚本眼里都是「带编号的条目」，长得一模一样。

所以闸门**只报观察，不判对错**。命中原句打出来，由作者判断：

- 作者**要了**主线 → 这是查漏
- 作者**没要**主线 → 这是抓 AI 自己加戏

---

## 11. 反模式

1. **给没有主线的卡套迷雾** —— 纯肉卡没有「后面才会发生的事」，没有可剧透的东西。rouka 是范本：25 段 259 条，玩法 118 条、事件链 30 条、塑造轴 9 条，唯一的剧情条目是「第一幕」1 条，而且只演一次。
2. **把「阶段」当成「剧情」** —— `阶段·C1_神物` 是状态档（这一档她什么样），`主线·第1集` 是排期（这一集发生什么）。前者全是现在时，不需要迷雾。
3. **靠一条 system prompt 元规则防剧透** —— 实测无效，见 §8。
4. **把未来的值从条目里删掉就完事** —— 删掉的是信息，不是问题。正确做法是**换个家**：恒定成立的事实留在人物条目，随时间变的值搬进排期条目。
5. **只看关键词不看字段名** —— 最严重的泄漏（那张卡的 58 条）一个剧透词都没有。

---

## 12. 动工顺序（一次实测修复的流程）

1. **抓包**：导出真实请求，看清每轮到底送了哪些条目进去。别靠读源码猜。
2. **逐条过判据**：给每条写「这条正文里哪句在说以后」，列成施工单。
3. **先改常驻**：`constant: true` 的条目每轮都在，泄漏影响最大，先改。
4. **按「一个事实一个家」搬**：恒定成立的事实留人物条目，随时间变的值搬进排期条目。
5. **复跑**：改完重新抓包，对比同一轮的 prompt。

这份 skill 的闸门（`scripts/gate.mjs` 检查 11）只做**与卡无关的观察** ——
字段时态、排期标记、跨条目重复事实。它抓得到「碳化率百分之十四」这种，
抓不到语义层面的剧透。语义那层必须人读。
