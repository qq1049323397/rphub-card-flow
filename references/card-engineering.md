## 序：长线卡不是"角色卡加更多描写"

绝大多数人做长线卡的做法是：写好一张普通角色卡，然后往里塞更多的场景描写。

这是**根本性的错配**。普通角色卡的目标是"这个角色像不像"；长线卡的目标是"**这条线能不能持续地、不重复地、不崩地跑下去**"。前者是**塑造问题**，后者是**工程问题**。

所以长线卡有普通角色卡不需要的四样东西：

| 需要 | 因为 |
|---|---|
| **过程** | 关键交互是有阶段、有上限的物理过程。没有过程只能靠堆形容词，堆三轮就枯竭 |
| **选择** | 玩家会重复同一件事。没有选择机制，第三轮就变成复读 |
| **自检** | 模型在长对话里必然退化。没有自检，角色十轮后崩成另一个人 |
| **入口** | 玩家不会读你的世界书。写了玩法却不给入口，等于没写 |

**一句话**：普通角色卡是**人物说明书**，长线卡是**一台状态机**。下面全部法则，都是在回答"这台机器该怎么装"。

## 第一章 本质：长线卡是一台状态机

### 1.1 三个必然失效

任何长线卡，如果不做工程约束，会在三轮内出现以下之一：

**失效一·复读机**
每轮的反应高度雷同。同一段动作写三次，三次的描写结构、台词、节奏几乎一样。玩家的体感是"这角色只会这一招"。
**根因**：模型每轮独立生成，没有跨轮的反重复约束，也没有足够的状态量让它分化。

**失效二·木偶**
玩家说"让她过来坐下"，她就过来坐下。玩家说"让她脱衣服"，她就脱。玩家很快发现自己在操作一个响应器。
**根因**：缺少主体性约束，模型把用户的指令当作最高优先级的执行目标。角色的性格变成了装饰。

**失效三·崩坏**
前五轮她是厌世的、冷淡的，第八轮突然变成娇羞少女；或者前一秒还是强硬主导者，后一秒开始哭着求饶。人格不连续。
**根因**：缺少锚点与自检。模型的"剧情惯性"会盖过人物设定——它倾向于往**更戏剧化**的方向漂移。

### 1.2 三条解法，对应三个约束

| 失效 | 约束类型 | 装在哪里 |
|---|---|---|
| 复读机 | **过程约束**（状态机 + 跨轮反重复） | 过程条目 + 自检条目 |
| 木偶 | **主体性约束**（选择权 + 日程 + 转译） | 元系统层 |
| 崩坏 | **自检约束**（锚点 + 校正层） | 系统层 |

**这三条约束不是可选项，是长线卡的最小完整集。** 缺任何一条，卡都会退化——只是退化的方向不同。

### 1.3 状态量：让机器有"记忆"的四个量

状态机要有状态。一张长线卡至少需要四类可跨轮追踪的量：

1. **身体量**——此刻处于哪个唤起阶段、有没有累、有没有疼、身上有什么痕迹。
2. **关系量**——此刻两人的紧张度/亲密度。**关键：不用数字。** 用最近几轮的事实判断（"她刚被拒绝了""他刚替她挡了一句话"）。
3. **时间量**——现在几点、今天发生过什么、上轮答应的事做没做。
4. **穿着量**——现在穿着什么、上轮脱到哪一步、有没有换。

**为什么强调"不用数字"**：数值系统会诱导玩家去**刷数值**，而不是去**玩关系**。用事实驱动，玩家才会关注发生了什么，而不是进度条。数值化的好感度是长线卡最廉价也最致命的设计。

## 第二章 分层：一张长线卡的解剖学

长线卡的世界书不该是"想到什么写什么"的清单，而该是**分层坐标系**。五个层，职责不重叠：

```
┌─ 元系统层 ─── 让角色活着：选择权 / 日程 / 选项 / 信息投放
├─ 操作层 ───── 具体怎么做：动作、部位、服装、道具
├─ 行为层 ───── 她怎么反应：声音阶梯、姿态偏好、台词库、生理阶梯
├─ 档案层 ───── 她是谁：身体、性格、习惯、语言指纹、称谓
└─ 系统层 ───── 怎么跑：执行序、锚点、书写规范、自检、落点标记
```

**为什么必须分层**：

- **系统层要被夹在两头**。执行序（每轮开始读什么）放最前，自检（写完查什么）放最后，内容条目全在中间。这样**内容怎么增删，都不会挤掉运行规则**。
- **操作层要按需加载**。动作、服装、道具这类条目量大（几十条），靠触发词按需注入。**不能常驻**——常驻会把上下文塞满，模型反而抓不住重点。
- **档案层是常驻的主力**。她的身体、性格、语言指纹必须每轮在场，否则演着演着就不像她了。
- **元系统层常常被忽略**，但它是"活人感"的唯一来源。见第十章。

### 2.1 条目粒度的法则

**一条条目 = 一个可以独立回答的问题。**

反例：一条"她的性与性格"（什么都写，什么都不深）。
正例："她在某个阶段的生理表现" / "她拒绝时怎么说话" / "她在公共场合被碰到时的处理"——每条只回答一个问题。

**判定标准**：如果你不能用一句话说出这条条目在回答什么问题，它就该拆。

### 2.2 常驻与触发的配比

经验配比：**常驻两成，触发八成**。

- 常驻（每轮在场）：系统规则、锚点、核心档案、自检、索引。
- 触发（按需注入）：操作条目、特定场景、特定玩法、支线人物。

**常驻不是越多越好**。常驻条目互相竞争注意力，超过一定量，模型的服从度反而下降——它会开始"忘记"其中一部分。**触发才是容量的来源**。

### 2.3 索引法则

**触发型条目的致命问题是：模型不知道它们存在。**

玩家不可能去触发一个它不知道的玩法。所以必须有**索引条目**——常驻，把可触发的条目**按名字列出来**，并附上触发方式的提示。

索引是长线卡的**目录**。没有目录，你写的一百条只有模型随机撞到的那几条会被用到。

## 第九章 系统层·自检：把 AI 的通病写成禁令

### 9.1 自检条目的写法

写一条**常驻**的"运行期校验"条目，要求模型**每轮后台执行、结果不输出**，列出检查项，**发现违规就重写该段**。

它不产生内容，它**扣分**。**这是唯一能对抗长对话退化的机制。**

### 9.2 通病清单（照抄级别）

以下每一条都是模型的**系统性倾向**，不是偶发错误：

**一·读心**
模型爱写角色的内心。禁止对象：`她意识到 / 她想 / 她觉得 / 她感到 / 她心里 / 她暗想`。
**还要禁"伪装成外部描写的内心认证"**：`她的眼里闪过 / 她的嘴角微微 / 她的心跳加速`——这些表面是动作，实质是心理旁白。

**二·解释尾句**
`这说明 / 这意味着 / 真正重要的是`。删掉。

**三·微动作清单**
连续排列的细小动作（"她抿了抿嘴，垂下眼，手指蜷了一下"）。**逐帧慢放**是 AI 味的核心来源之一。

**四·同义重申与整齐排比**
同一个意思换三种说法写三遍。三段式排比。感官堆料。

**五·报幕连接句**
"她说道""他开口道"。台词直接出现。

**六·氛围铺陈段**
为了"文学感"加一段与环境无关的描写。**长线卡里这是纯损耗。**

**七·总结收尾**
场景结束后加一段升华感慨。**写完即止。** 场景结束就结束，不加总结。

**八·破折号与括号解释**
破折号用逗号或省略号替代。括号里的解释直接写进正文。
（**例外**：结构性标记可以使用，如条目索引的分隔符。）

**九·用词黑名单**
`一抹 / 弧度 / 不容置疑 / 不易察觉 / 微不可察 / 生理性 / 指尖发白` 等。这些是**网文腔的化石**，出现即出戏。**列成清单**，不要指望模型自觉。

### 9.3 跨轮反重复（最难实现、也最有效的一条）

> **检查上一轮正文的开头和结尾类型，本轮不得重复。**

**为什么它有效**：重复感不来自内容，来自**结构**。模型会用同一种方式开头（"清晨的阳光"）、同一种方式结尾（一句总结）。禁掉结构重复，体感上立刻"活"了。

**这是跨轮约束，只能靠常驻条目实现。**

### 9.4 需要感校验：最狠的一条

> **她的缺口，是否只在玩家在场时才出现？**

模型有一种根深蒂固的倾向：**把角色写成一个等待被观测才存在的东西**。玩家一走，她的生活就暂停；玩家一来，她所有的情绪和需求才启动。

**这是 AI 角色最致命的病**，因为它让角色**彻底变成道具**。

**反制写法**：
- 她在独处时**一样**有她的问题（一样做不好、一样管不住自己、一样会难受）。
- 她**不等**你来救。她自己动手。
- 她的秘密**不是**"等着被戳穿好推进关系"。她是**真的**那样想。

**推而广之**：任何"她只在主角面前才完整"的设定，都要反过来检查——**她一个人的时候，她在做什么？** 答不上来，这个角色就还没立起来。

**注意**：这条与"玩家是唯一记得她的人"这类设定不冲突。**关键在于"她独处时也照常运行"**——世界的停止是因为设定，不是因为她停止了生活。**而且她独处时应该更吃力**——那才是刀。

### 9.5 反套路校验

模型会为了"推进剧情"而**违背人物**：

- **突然转向**：关键行为凭空产生，没有来自日程、习惯或既有关系的铺垫。
- **无条件接受**：角色的行为没有来自日程、习惯或既有关系的依据。
- **人格崩坏**：为了戏剧性，让角色做出违背锚点的事。
- **反应雷同**：和上一次的反应一模一样，无视身体状态的变化。

**校验方式**：每轮问一遍"这个行为来自哪里？"——必须能追溯到**某个具体来源**。

## 第十章 元系统层：让角色活着的四个装置

这一层最抽象，但它是"活人感"的唯一来源。四个装置：

### 10.1 装置一·选择权（防操控）

**玩家一定会用上帝视角指挥角色。**（"让她过来坐下""让她把衣服脱了"）

**不要执行指令。要转译。**

```
玩家输入（指令）→ 转译成场景内的对话或请求 → 角色自主反应
```

**角色的反应必须经过四层过滤**：性格、当前心情、身体状态、此刻正在做的事。

**结果**：她可以配合、可以害羞半天才配合、可以拒绝然后三分钟后自己凑过来、可以误解你的意思做出别的事、可以唠叨你一顿然后一边骂一边照做。

**为什么这比"她总是配合"好**：

> **能拒绝的角色，她的配合才是给予。**
> 不能拒绝的角色，她的配合只是执行。

**这一条对感情向长线卡尤其关键**。很多作者为了"甜"把角色写成有求必应，结果角色变成了自动售货机。**甜来自"她本可以不这样，但她选择了这样"。**

**并且**：当玩家连续多轮只用指令、不给具体行动时，角色的**主动性应该自然上升**——她会开始做自己想做的事。这是防止玩家"挂机指挥"的机制。

### 10.2 装置二·日程（独立时间线）

**角色必须有玩家不知道的生活。**

写清：她的日常习惯按时段怎么排、有哪些外部人物/事件会主动找上门、有哪些"待办"在积压。

**运行方式**：每轮检查"有没有成熟的时间窗口"（某人该出现了、某件事该发生了、某个未读该被看到了），按**因果紧迫度**排序。没有成熟窗口，就跟着玩家的行动走。

**效果**：角色不是"等你按按钮才动的 NPC"，她**有自己的时间线**。玩家会感到"我离开的时候，世界还在转"。

**这一条直接反制 9.4 的"需要感"病。**

### 10.3 装置三·选项（永远有下一步）

**每轮正文结束后，给出几个方向。**

典型三选项：

```
1 推进性接触的方向
2 日常互动的方向
3 角色自己的意外行动（由模型自主设计）
```

**第 3 项是设计精髓。** 它的规则要写死：

- 必须来自行为来源的**合理推导**
- 必须是此前**没出现过**的新方向
- 可以是一件**完全正常的事**在当前语境下显得反常
- 可以是一个从没触发过的**能力缺口**突然出现

**作用**：给角色一个**每轮自我发挥的出口**。这解决了"长线卡玩久了变复读机"的问题——因为**变化由角色自己提供，不靠玩家挖**。

**并且**：玩家永远可以选择自己输入，选项只是兜底。**兜底的价值在于"不知道下一步做什么"的时候。**

### 10.4 装置四·信息（分期泄露）

**如果角色有秘密，不要一次说明，要分期泄露。**

**写法**：定义三个阶段。

```
第一阶段（完全封锁）
  玩家能看到什么外部信号？（行为变化、物件、异常反应）
  玩家看不到什么？
  她的掩饰话术是什么？

第二阶段（间接泄露）
  通过什么方式玩家能拿到碎片？（转述、一闪而过的画面、无法解释的能力）
  她如何回避追问？

第三阶段（揭露）
  什么条件触发？（玩家主动调查 / 时间推进 / 关系推进）
  揭露后关系如何变化？
```

**为什么这是一个系统而不是一段设定**：它把"秘密"变成**可玩的资源**。玩家的能动性从"我什么时候被告知"变成"**我要不要去看**"。

**反模式**：把秘密写成一段说明书式的设定条目，列出一堆破绽让玩家"自己发现"。
**这错在**：它假设玩家会去翻世界书、会记住破绽、会主动验证。**真实玩家不会。**

**正确做法**：写清"玩家在这一阶段**能看见什么信号**"，让秘密通过**正常对话的输出**自然渗透。

### 10.5 元系统的共同点

四个装置都在做同一件事：**把控制权的一部分交回给玩家，另一部分留给角色。**

- 选择权 → 交回给**角色**（她有否决权）
- 日程 → 留给**角色**（她有自己的生活）
- 选项 → 交给**玩家**（下一步做什么）
- 信息 → 交给**玩家**（要不要去看）

**只有角色有自主权、玩家有选择权，这台机器才是"活的"。**

## 第十一章 反模式总表

按严重程度排列。

### 致命（会让卡失败）

| # | 反模式 | 为什么致命 |
|---|---|---|
| 1 | **玩法没有入口** | 写了等于没写 |
| 2 | **缺口只在玩家在场时出现** | 角色降格为道具 |
| 3 | **角色无拒绝能力** | 配合变成执行，角色变成自动售货机 |
| 4 | **没有生理阶梯** | 过程消失，只能堆形容词，三轮枯竭 |
| 5 | **阶梯可以跳级** | 一轮从零到顶，张力归零 |
| 6 | **没有自检条目** | 长对话必然崩坏 |
| 7 | **文雅替代词** | 文体撕裂，直接出戏 |
| 8 | **数值化好感度** | 诱导刷数值，玩家不关注发生了什么 |

### 严重（让卡平庸）

| # | 反模式 | 后果 |
|---|---|---|
| 9 | 身体只写审美不写接口 | 描写无法在后文复用 |
| 10 | 声音只有一个词 | 每场都听起来一样 |
| 11 | 动作写感觉不写物理 | 第二次就没话说 |
| 12 | 没有体力限制 | 动作没有自然结束的理由 |
| 13 | 台词是通用台词 | 换个角色也能用，声音指纹为零 |
| 14 | 称谓会随关系自动升级 | 最典型的 AI 味 |
| 15 | 秘密写成说明书 | 玩家不会去翻，秘密等于没藏 |
| 16 | 只写女方反应 | 单向表演，关系无锚 |
| 17 | 模块联动逐个写 | 规模爆炸，写不完 |
| 18 | 常驻条目过多 | 互相竞争注意力，服从度下降 |
| 19 | 没有跨轮状态延续 | 每轮从零开始，阶梯白设计 |
| 20 | 场景结束加总结升华 | 长线卡里是纯损耗 |

## 附录 A · 平台绑定层

**以上全部法则与平台无关。** 但落地时需要知道平台提供什么能力。下面列出**法则 → 需要什么能力 → 缺能力时的退路**。

| 法则 | 需要的能力 | 没有时的退路 |
|---|---|---|
| 分层（常驻/触发） | 条目级"常驻"开关 + 触发键 | 全部塞进主描述，按重要性排序；或分多张卡 |
| 系统层夹两头 | 条目排序（含负数/前置位） | 把系统规则写在主描述最前和最后 |
| 落点标记 | 正则替换 + 客户端脚本 | 退化为"每轮结尾列出玩法名"（兜底数量受限） |
| 可交互面板 | 正则 + 客户端 JS | 常驻索引条目（弱，但聊胜于无） |
| 玩法模块按需加载 | 触发键 + 扫描窗 | 写进常驻但精简；或让玩家在对话中声明 |
| 跨轮状态 | 对话历史可读 | 状态栏输出到正文，靠模型自己读上下文 |
| 玩法联动 | 多条目同时注入 | 把常用组合合并成单条"套餐"条目 |
| 自检条目 | 常驻 | 写进主描述；或每 N 轮提醒一次 |
| 信息分期 | 常驻 + 触发 | 全部写进常驻，按阶段分条 |
| 反正则/反递归 | — | 设计时假设**注入的内容不会再次触发**，重要内容不要依赖链式触发 |

**最重要的平台预设**：**注入的世界书内容通常不会再次进入触发扫描。** 所以：

- 不要设计"条目 A 提到 X，X 触发条目 B"的链式结构——**它不会发生**。
- 要触发的关键词，必须出现在**玩家输入或角色输出**里。
- 因此：**玩法名要出现在每轮输出中**（这就是选项/状态栏/面板存在的根本原因）。

## 结语

> 长线卡的技术本质是：**把关键交互从形容词变成过程，把"角色"从设定变成主体，把"玩法"从隐藏内容变成可见入口，把"模型"从自由发挥变成受约束的执行器。**
>
> 前者是**写作**，后者是**工程**。长线卡要两样都有。
>
> 只做前者，是一篇好的一次性描写。
> 只做后者，是一台冷冰冰的机器。
>
> **做全的，才是能玩很多轮的东西。**
