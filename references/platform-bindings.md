# 平台绑定矩阵

> 配套 `design-principles.md`。那里声明能力（C1–C7），这里说明各平台如何满足。
> **核实日期：2026-09-30。** 平台与插件迭代较快，使用前请复核标注为"待确认"的条目。
> 来源见文末。

## 一、绑定矩阵

| 能力 | RP-Hub | SillyTavern |
|---|---|---|
| C1 状态持久化 | **原生**：平台变量状态 + 按字段合并语义 | **原生偏弱 + 插件**：原生变量分聊天/全局两套；按楼层记录的完整方案靠第三方插件 |
| C2 正文标记 → UI 渲染 | **原生**：UI 模板 + iframe 沙箱 | **原生正则 + 插件**：正则替换成 HTML；iframe 沙箱交互靠第三方插件 |
| C3 富交互回传 | **原生**：触发斜杠命令接口 | **插件**：酒馆助手提供触发接口；原生 STScript 亦可 |
| C4 楼层级存档与恢复 | **原生**：楼层快照 + 记录回扫 | **原生但机制不同**：聊天文件 + 分支功能 |
| C5 条件分支渲染 | **原生**：模板变量条件 | **插件**：模板插件（EJS）条件 |
| C6 模板变量替换 | **原生**：双花括号占位符 | **原生宏 + 插件**：平台宏；复杂逻辑靠模板插件 |
| C7 递归触发 | **无**：完全不支持递归 | **原生**：支持递归，且可分层控制 |

## 二、SillyTavern 侧插件依赖

平台**本身只提供世界书 + 正则**。下列能力需第三方插件补齐：

| 插件 | 补的能力 | 说明 |
|---|---|---|
| 酒馆助手（JS-Slash-Runner） | C2、C3 | 提供 iframe 沙箱执行环境与完整脚本 API；平台默认不支持直接执行 JS |
| MagVarUpdate（MVU） | C1 | 按楼层记录变量更新，不依赖过往楼层 |
| 模板插件（ST-Prompt-Template） | C5 | EJS 模板语法做条件渲染与变量读取 |

**重要**：装插件意味着**依赖外部 CDN**，与反模式 4（单一外部域）冲突。
每装一个插件，都要回答"它挂了这张卡还剩多少能用"。

## 三、不装插件时的降级表现

| 能力 | 无插件时的实际表现 |
|---|---|
| C1 | 仅能用平台原生变量；无按楼层记录，变量一致性需自行设计 |
| C2 | 正则可渲染静态 HTML；无 JS 交互（动画/点击响应失效） |
| C3 | 仅能用平台命令；无插件则按钮回传需另寻方案 |
| C5 | 无 EJS 则不能做条件分支，只能全量输出 |
| C6 | 平台宏可用，复杂逻辑不可用 |

**设计建议**：把"无插件也能玩"当作降级底线。
UI 退化成纯文本时，正文仍然完整可读 —— 这是 C2 的正确设计姿态。

## 四、两平台的关键差异（写卡时必须知道）

1. **递归**：一边完全不支持，一边原生支持并分层。
   → 见 `design-principles.md` §3：**默认假设无递归**。
2. **中文词边界**：一边没有此概念；另一边有"整词匹配"开关，**中文下必须关闭**，否则中文连续文本会被误判。
3. **正则写法**：一边由独立字段声明"按正则匹配"；另一边把正则写成带斜杠与 flag 的字面形式。
   逻辑可平移，格式要改。
4. **正则反噬世界书**：某一平台的正则可作用于**世界书内容本身**，且 `promptOnly` 类脚本会覆盖显示层过滤 ——
   结果是"玩家看到的"和"模型读到的"不一致。写正则前确认它作用在哪些文本源上。
5. **变量作用域**：一边是平台托管的统一状态；另一边分聊天变量、全局变量、按楼层变量，两套持久存储互不同步。

## 五、待确认项（不替使用者赌）

1. **MVU 的两代写法并存**：官方教程（master）仍使用 `[值, 说明]` 二元组描述变量；
   而有社区实战文档称该格式已废弃、描述职责改由 schema 的 `.describe()` 承担。
   **本文件不选边**，使用前请以实机为准。
2. 插件字段细节随版本变动，本文只写能力与依赖关系，不写具体字段代码。
