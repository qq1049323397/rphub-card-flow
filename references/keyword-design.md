# 关键词设计：从场景长出来，不从内容总结出来

> 来源：2026-09-23 审计用户上传的《世界书关键词审查修理》skill，取其可执行部分，
> **剔除其中与 RP-Hub 源码冲突的说法**（见 `key-reachability.md` 裁决表）。
> 本文档只保留在 RP-Hub 上验证成立、且本插件工具未覆盖的设计方法。

## 一、三段设计法（设计侧核心）

**严禁把键从条目内容里总结出来塞进 keys。** 这是最隐蔽的坏卡流水线：
逐条给每个条目配上"看起来对"的词，死键率必然是 0，但键全是泛词，问题全在误触发。

正确顺序：

1. **先定场景需求**：这条目回答玩家的什么行动 / 到访什么地点 / 处于什么阶段？
   先有场景，后有条目。没有场景需求就不该有这个条目。
2. **再查现有机制能否养活它**（见下表）。**没机制 → 先补机制再谈键。**
3. **最后设计键**：键 = AI 被契约逼着写的槽位值，或行为发生词。

### 机制优先级表（RP-Hub 口径）

| 机制 | 键怎么被养活 | 可靠度 | RP-Hub 支持 |
|---|---|---|---|
| 输出契约（状态栏/场景头每轮必写） | 键 = 槽位值枚举（地点/时辰/阶段） | 最高（每轮必进窗） | ✅ 靠 prompt 约定 + 正则承接 |
| 常驻索引条目 | 上游正文点名下游条目名 | 中（每轮进 prompt） | ✅ `constant:true` |
| 开场白 UI 按钮 | 点击送字面 | **低**（预填，需玩家按发送） | ⚠️ `data-slash` + `triggerSlash` |
| 思维链 CoT 引导 | 常驻法则要求 AI 复述状态 | 中（靠服从性） | ✅ 写进常驻 |
| `probability` | 低频条目用概率补偿 | 辅助，不能当唯一通道 | ✅ |

**注意**：`triggerSlash` 不是"点了就触发"。它把文本存进 `pendingCardInteraction` 并聚焦输入框，
**仍需玩家按发送**（`app.js` L7723-7735）。别把它当可靠入口。

## 二、短键原则（部分成立，需要精确表述）

原 skill 的「非专有名词一律 ≤2 字」是一个**有用的启发式，但不是铁律**。实测：

- 键匹配是**大小写不敏感的子串匹配**（`useRegex=false`），
  正文/输入必须逐字包含键才命中。所以长键确实降低召回率。
- 但实测某张范本卡 2 字键与 3-4 字键命中率都是 99%（因为该卡键都进了常驻索引），
  说明**键长不是决定因素，键是否被机制养活才是**。
- 真正的问题在**链式依赖**：键只出现在自己条目正文里，就只可能靠上游带动。

**可执行版本**：
1. 同一概念的近义词**各拆各键**（keys 数组本身就是 OR），不要合成一个长短语。
2. `useRegex=true` 时，弹性来自**分支粒度**：
   ✅ `(?:请仙|典仪).{0,8}(?:遇刺|陨落)`
   ❌ `(?:请仙典仪帝君遇刺)`（一个长分支，等同长字面键）
3. 专有名词（人名/地名/组织/作品/功法/编号令牌）**整体保留**，拆开反而误触发
   （`希`/`尔` 会命中一切）。
4. 契约槽位枚举值**必须逐字等于**枚举，不可为凑短改写 —— 不对齐比长键更糟。

## 三、误触发：比死键更隐蔽的病

死键看得见（键哪都不出现），误触发看不见（键哪都出现）。

| 病灶 | 症状 | 处方 |
|---|---|---|
| 泛词键 | `擦过`/`额头`/`闷哼` 这类跨场景词，玩家写"发烧额头烫"也拉进官能条目 | 换**行为发生词**短键 + 挂 `probability` |
| 键 = 状态栏槽位值 | 每轮必写的枚举值全成了键 → 该组条目**每轮全进** | 检查密度；槽位值键只给"每轮都该在场"的条目 |
| 人名键拉官能内容 | 人名一出现官能条目必进，无论场景是否色情 | 改动作词键或挂概率 |
| 键覆盖全卡 | 见"照着内容生成"流水线 | 重做三段设计 |

**密度基准**：单轮平均拉取 5-6 条健康，7-8 可接受，10+ 过高，30+ 病态。

自检方法：写 3-10 组该卡实际玩法的模拟正文（含卡自己的状态栏/锚点格式），
跑字面匹配，数单轮拉取条目数并定位误触发。

## 四、必须核的三件事（交付前）

1. **契约-键名对齐**：输出契约要求的枚举词，与条目键是否**逐字相同**？
   两套命名（UI 变量「序章/博弈交锋」vs 条目键「第二阶段/第三次博弈」）= 键白设。
2. **承接正则不吞令牌**：`replaceString` 不含 `$1` / `{{match}}` 时，整行替换会抹掉令牌，
   下一轮扫不到 → 令牌键全灭。**令牌键必须验 `$1` 保留。**
3. **时机限定写在正文里**：阶段条目正文没写"仅当第 X 阶段生效" → 早期就剧透后期内容。
